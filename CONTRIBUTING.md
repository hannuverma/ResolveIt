# Contributing to ResolveIt

Thank you for your interest in contributing to ResolveIt! This document provides guidelines for contributing to the project.

## Getting Started

1. Fork the repository
2. Clone your fork: `git clone https://github.com/YOUR_USERNAME/ResolveIt.git`
3. Create a new branch: `git checkout -b feature/your-feature-name`
4. Make your changes
5. Test your changes thoroughly
6. Commit your changes: `git commit -m "Add: description of your changes"`
7. Push to your fork: `git push origin feature/your-feature-name`
8. Open a Pull Request

## Code Style

### Python (Django)
- Follow PEP 8 guidelines
- Use meaningful variable and function names
- Add docstrings to functions and classes
- Keep functions focused and small

### JavaScript/React
- Use functional components with hooks
- Follow ESLint configuration
- Use meaningful component and variable names
- Keep components small and reusable

### Git Commit Messages
- Use present tense ("Add feature" not "Added feature")
- Use imperative mood ("Move cursor to..." not "Moves cursor to...")
- Limit the first line to 72 characters or less
- Reference issues and pull requests liberally after the first line

Examples:
- `Add: user authentication feature`
- `Fix: complaint submission validation bug`
- `Update: department leaderboard styling`
- `Refactor: complaint serializer logic`

## Pull Request Process

1. Ensure all tests pass
2. Update the README.md with details of changes if applicable
3. Update documentation if you're changing functionality
4. The PR will be merged once you have approval from maintainers

## Reporting Bugs

Before creating bug reports, please check existing issues. When creating a bug report, include:

- **Summary**: Clear and concise description of the bug
- **Steps to reproduce**: Detailed steps to reproduce the behavior
- **Expected behavior**: What you expected to happen
- **Actual behavior**: What actually happened
- **Screenshots**: If applicable
- **Environment**: OS, browser, Python version, Node version, etc.

## Suggesting Enhancements

Enhancement suggestions are tracked as GitHub issues. When creating an enhancement suggestion, include:

- **Clear title and description**
- **Use case**: Why this enhancement would be useful
- **Possible implementation**: If you have ideas on how to implement it

## Development Setup

Refer to the main README.md for detailed setup instructions for:
- Backend (Django)
- Frontend (React)
- AI Layer (Node.js)

## Code Review Process

All submissions require review. We use GitHub pull requests for this purpose. Reviewers will check for:

- Code quality and readability
- Test coverage
- Documentation updates
- Adherence to project structure and conventions

## Questions?

Feel free to open an issue with the `question` label if you have any questions about contributing.

Thank you for contributing to ResolveIt! 🎉
